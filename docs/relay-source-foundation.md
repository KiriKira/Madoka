# T1：中继来源基础层

`rtcmedia` 的 `RelaySources` 为当前节点准入和静态 TURN 提供纯 Kotlin 来源模型及合并规则。
`RtcAudioSession` 的可选 `additionalRelaySources` 参数在 native peer 创建前接入静态来源；未传入或全部关闭时，
节点下发的 URL 顺序、分组、重复项及可选凭据保持原样。该基础层不获取网络凭据、不提前申请媒体准入。

- 静态来源保留自定义端口、TLS 5349 和 IPv6；Cloudflare 端口筛选不放在通用层。
- 多来源模式仅合并 URL、用户名、密码均相同的项，保留来源 ID 映射。来源 ID 是受限字符集的诊断标识，非来源 URL 或用户展示名称。
- 默认配置上限为 8 个来源（含当前节点）、16 组 ICE server、32 个 URL；实际 native 候选仍受现有 128 上限约束。
  URL 数不是候选数估算，仍须模拟器多网卡/IPv4/IPv6 验收。节点单来源兼容路径不新增配置裁剪。
- 统计日志通过本地 relay candidate 的 URL 查询来源 ID；无法归属时显示 unknown，直连显示 direct。
  不输出来源 URL、用户名或密码；同凭据的来源别名全部保留，不宣称能够区分同一配置来自哪个别名。

本批尚未完成整个 T1。静态来源目前为模块注入接口，尚未接入设置页或持久化；网络来源、过期缓存、自动择优和二维码属于后续工作。
同 URL 不同凭据会完整保留在解析结果，但固定 SDK 的实际回退尚未验证；native 适配边界明确拒绝此组合
（`relay_credential_fallback_required`），防止静默丢弃可用凭据。只有实现并验证有界回退后才能放开。

本机新增的单元测试覆盖单来源兼容、端口、IPv6、去重/不同凭据、输入验证、关闭来源、数量限制及诊断脱敏。
两端构建与测试结果见配套 PR。T1 的强制中继通话、来源日志实际归属及候选预算仍需 KVM 模拟器或真机验收；
当前开发机器没有 `/dev/kvm`，没有以纯单元测试代替媒体通话验收。
